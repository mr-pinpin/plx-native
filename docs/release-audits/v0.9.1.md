# Release audit — v0.9.1

Evidence for the [PinPin local-server release note](https://github.com/mr-pinpin/plx-native/blob/release/v0.9/docs/release-notes/v0.9.1.md). This fork starts from upstream v0.9.0. Its account-free mode is explicit and does not claim to change Plex Media Server licensing or the server's own authentication policy.

## Device test evidence

The intended test television is an LG OLED55A3RLA reporting webOS 10.3.2. The upstream v0.9.0 native application was installed and its account-link screen was observed by the owner. This establishes the original installation, not the new mode's playback behavior.

The household Mac mini runs an unclaimed Plex Media Server with an explicit home-network authentication exception. Requests from the television returned its identity, and local UDP discovery identified the same server. The server indexed existing movie and episode files; an actual media range request returned valid container bytes. No Plex account was created. Actual modified ARM client playback remains pending when this candidate is prepared.

## External compatibility reports known at release time

No external report verifies this fork's account-free extension. Upstream playback reports are not promoted into claims for the new mode.

## Compatibility tiers, and what moved

No model is promoted to a newly verified playback tier by host tests or the static firmware checks. The first candidate is intended for the single household test set described above.

## Known issues at release, with provenance

The television's ordinary resolver could not resolve the Mini's local hostname in a direct test. Server discovery therefore includes a bounded broadcast fallback, which did receive the configured Mini's reply from the TV; multicast alone was not sufficient on this network. The server identity in discovery is a trusted-LAN selector, not cryptographic authentication.

## Deliberately not done

No account or subscription is provisioned. No original media files are moved or duplicated. The extension does not add a decoder or renderer, claim broader model compatibility, or replace the television's factory launcher. Device playback, frame pacing and decoder behavior cannot be established by the host suites and await the candidate's hardware check.

## Release configuration

The candidate uses the stable application identity with RELEASE=1 and is built through the existing shared ARM package workflow. External telemetry is explicitly disabled for this fork; package, ELF, firmware and corresponding-source gates remain. The pinned toolchain and dependencies are unchanged. Device-local configuration is outside Git and contains no account token.
